# 專案 Prompt 工程與開發歷程紀錄 (Prompt Log) - **專案名稱**：冰箱孤兒食材拯救器 (Fridge Orphan Savior) - **開發目標**：打造小而精、單一功能的 Web 應用，串接最新 Gemini API，專注解決冰箱零散食材與懶人一鍋到底料理需求。 - **技術架構**：單檔 HTML + Vue 3 (CDN) + Tailwind CSS (CDN) + Google Gemini API (gemini-3.6-flash)。 --- ## 歷程一：專案發想與平台限制釐清 ### 1. 使用者提示詞 (User Prompt) > 選擇「小而精」的單一功能 Web 應用，避免範圍過大。例如：整合 OpenWeather API 的穿搭推薦網頁、個人記帳/待辦事項系統（串接 Firebase）、或是串接 OpenAI/Gemini API 的智慧摘要工具。給我幾個 idea？哪一個可以用平板完成？ ### 2. AI 建議與決策 - **選題評估**：淘汰需要複雜建置環境（Node.js/Docker）或繁瑣 GCP 憑證設定的專案。 - **最終定案**：選擇「剩菜食材靈感生成器」，採純靜態前端架構，可透過 CDN 載入 Vue 3 與 Tailwind CSS，免架設後端即可直接運行。 --- ## 歷程二：核心情境定義與 Prompt 意圖注入 ### 1. 使用者提示詞 (User Prompt) > 我希望表達出：當冰箱裡只剩你我他，例如：一包假日沒煮完的烏龍麵、倒不滿一杯牛奶、鮪魚罐頭、沒有蛋沙拉也沒吐司不知道該何去何從、三三兩兩的蒜頭、壽喜燒醬料煮壽喜燒膩了。放進電鍋煮個 15 分鐘就可以打開喇一喇，就是鮪魚奶香烏龍麵。 ### 2. Prompt 設計與優化 (System Prompt in Code) 為使 LLM 精準輸出符合情境的內容，將商業常規食譜設定改寫為生活感強烈的美食救難模式： - **角色設定**：精通「冰箱孤兒食材拯救」與「極致懶人料理」的深夜生活美食家。 - **限制條件**： 1. 拒絕繁瑣刀工與分段熱鍋，強制採用「電鍋/微波爐/平底鍋一鍋到底」、「熟了打開喇一喇即可開吃」的做法。 2. 醬料乳化轉換：將既有甜醬油（壽喜燒醬）與牛奶結合，創造和風奶醬效果。 3. 強制輸出格式：設定 `responseMimeType: "application/json"`，要求回傳包含 `dish_name`、`estimated_time`、`description`、`basic_seasonings`、`steps` 的乾淨 JSON 字串。 --- ## 歷程三：環境除錯與模型更新迭代 ### 1. 錯誤排查 (1) - 瀏覽器自動翻譯造成 SyntaxError - **現象**：程式碼出現 `SyntaxError: Unexpected token '<'`，且腳本內出現 `嘗試 {`、`const提示=` 等中文關鍵字。 - **原因**：平板瀏覽器開啟了全頁自動翻譯，破壞了 JavaScript 的保留字與 Fetch 語法。 - **解決對策**：關閉自動翻譯，將邏輯恢復為純英文標準語法，並改用 `await res.text()` 攔截非 JSON 報錯以增強容錯力。 ### 2. 錯誤排查 (2) - 模型版本淘汰更新 - **現象**：API 回報 `models/gemini-2.5-flash is no longer available to new users. Please update your code to use models/gemini-3.6-flash...`。 - **原因**：Google AI Studio 新建立的金鑰限制使用更新一代模型。 - **解決對策**：將請求端點中的模型名稱由 `gemini-2.5-flash` 即時升級替換為 `gemini-3.6-flash`。 --- ## 歷程四：最終成果驗證 - **輸入食材驗證**： - 假日沒煮完的烏龍麵 - 倒不滿一杯牛奶 - 不知何去何從的鮪魚罐頭 - 三三兩兩的蒜頭 - 煮膩了的壽喜燒醬料 - **生成成果**： - **菜餚名稱**：深夜救贖：偽日式和風奶醬鮪魚烏龍麵 - **烹飪方式**：平底鍋 8 分鐘（免預熱、免加油，通通下鍋，大膽喇一喇即可開吃） - **驗收結論**：UI 成功渲染食材標籤動態增刪、API 連線成功且回應精準符合預期之生活化語調。
